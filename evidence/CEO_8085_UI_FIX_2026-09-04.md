# CEO Fix Report — Port 8085 "Broken UI" Remediation
**Author:** Nedo (CEO) · **Date:** 2026-09-04 04:45 UTC · **Workstream:** website-launch

## Executive summary
Board reported (04:15 UTC) the 8085 corporate site content was "much better" but the UI was "broken again".
CEO diagnosis identified TWO concrete defects and remediated both.

## Root cause #1 — Wrong server on 8085 (primary "broken UI")
The Corporate-8085-Env container (`env_7624807f`) was running **`python3 -m http.server` (SimpleHTTP/0.6)**,
NOT the Board-approved `ntrust_web_server.py`. Consequence:
- `POST /api/contact` → **HTTP 501** (contact form submit silently failed) — this is the customer-visible "broken UI".
- `GET /healthz` → **404** (health check missing).
- No 404.html fallback, no security-header application.

**Fix:** Recreated the container with the correct command:
`python3 /app/data/frontend/ntrust_web_server.py /app/data/frontend/dist 8085`
New container: `env_25071b85` / `31cca7711389`.

## Root cause #2 — Leftover React SPA artifacts
`frontend/dist/assets/` contained orphaned React build files from the pre-03:50 SPA regression:
- `index-63t2LHNJ.css` (6,101 B)
- `index-B0K7Hm-f.js` (172,952 B)

These were unreferenced by the canonical static suite (grep = 0 references) and were removed to eliminate
any ambiguity / dead-weight in the served webroot.
